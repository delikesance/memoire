\chapter{Problématique technique}
\label{chap:problematique}

\section{Écarts GDS / NDC dans le panier}

En billetterie B2B, une erreur applicative se traduit souvent par une vente bloquée, un voyageur empêché de partir, ou une pénalité financière.

Sabre, par exemple, conserve un état de session et peut bloquer des places pendant le parcours. Les API NDC raisonnent plutôt en requêtes indépendantes : l'offre vit le temps d'un identifiant temporaire. Metis Connect mélange les deux dans la même interface. Entre la sélection du vol et le paiement, après saisie des passagers, une classe peut se fermer ou des taxes peuvent être recalculées. Si l'application se contente de renvoyer une erreur opaque, l'utilisateur doit tout recommencer. S'ajoutent les contrôles sur les noms, le rattachement des bébés sans siège, les devises, et l'écriture de segments passifs destinés aux logiciels comptables des agences.

La question de page de garde résume ce périmètre. Certaines limites n'ont apparu qu'après plusieurs mois d'exploitation.

\section{Choix de conception}

Pour ne pas dupliquer la logique d'affichage, les réponses transporteurs sont ramenées à un modèle commun avant d'arriver au frontend. On a pu brancher de nouvelles compagnies sans réécrire les écrans du panier. Les offres « branded » ont ensuite forcé un champ fourre-tout côté métadonnées, faute de pouvoir tout typer proprement.

Sur la création d'ordre, un module d'appairage normalise les noms, rattache les nourrissons et retire les bagages orphelins. Le cas de deux homonymes sur le même dossier a nécessité un correctif ultérieur.

Lorsque le transporteur signale un conflit tarifaire, une modale affiche l'écart tout en gardant les passagers déjà saisis. Cela ne résout pas les situations où le vol n'existe plus.

Les paramètres d'écriture passive ont été isolés par point de vente, avec une règle empêchant une écriture redondante sur le second GDS.
