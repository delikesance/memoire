\section{Couche d'Abstraction Canonique via le Patron Adaptateur}

Pour éviter de saupoudrer le frontend de \texttt{if} par transporteur, j'ai introduit une couche d'adaptateurs. Sabre renvoie SOAP ou texte brut ; les passerelles NDC directes (Air France-KLM, British Airways, Aegean, Turkish) répondent en JSON ou XML.

Le module \texttt{SabreAdapter.ts} (listing \ref{lst:sabreadapter}) mappe ces payloads vers \texttt{CanonicalFlightOffer}. Recherche et panier manipulent ensuite une seule structure TypeScript, indépendante du protocole amont.

\begin{lstlisting}[language=TypeScript, caption={Adaptateur de normalisation des offres Sabre (\texttt{SabreAdapter.ts})}, label={lst:sabreadapter}]
export interface SabreFlightLeg {
  origin: string;
  destination: string;
  departureDateTime: string;
  arrivalDateTime: string;
  carrierCode: string;
  flightNumber: string;
  cabinClassCode: string; // 'Y', 'J', 'F', 'W', etc.
  bookingClass: string;
  operatingCarrier?: string;
}

export interface SabreAncillaryService {
  serviceId: string;
  serviceType: 'BAGGAGE' | 'SEAT' | 'MEAL' | 'PRIORITY';
  commercialName: string;
  amount: number;
  currency: string;
  segmentRefIds: string[];
}

export interface CanonicalFlightOffer {
  offerId: string;
  provider: 'SABRE_GDS' | 'SABRE_NDC';
  validatingCarrier: string;
  segments: Array<{
    id: string;
    origin: string;
    destination: string;
    departure: string;
    arrival: string;
    airline: string;
    flightNumber: string;
    cabin: 'ECONOMY' | 'PREMIUM' | 'BUSINESS' | 'FIRST';
  }>;
  ancillaries: SabreAncillaryService[];
  pricing: {
    baseFare: number;
    taxes: number;
    total: number;
    currency: string;
    taxBreakdown: Record<string, number>;
  };
}

export class SabreAdapter {
  public static mapCabin(code: string): 'ECONOMY' | 'PREMIUM' | 'BUSINESS' | 'FIRST' {
    const mapping: Record<string, 'ECONOMY' | 'PREMIUM' | 'BUSINESS' | 'FIRST'> = {
      'Y': 'ECONOMY', 'M': 'ECONOMY', 'K': 'ECONOMY', 'L': 'ECONOMY',
      'W': 'PREMIUM', 'E': 'PREMIUM',
      'J': 'BUSINESS', 'C': 'BUSINESS', 'D': 'BUSINESS',
      'F': 'FIRST', 'P': 'FIRST'
    };
    return mapping[code.toUpperCase()] || 'ECONOMY';
  }

  public static normalizeFlightOffer(raw: any): CanonicalFlightOffer {
    if (!raw?.id || !Array.isArray(raw?.flights)) {
      throw new Error("[SabreAdapter] Payload invalide : " + String(raw?.id));
    }

    const segments = raw.flights.map((leg: SabreFlightLeg, idx: number) => ({
      id: 'SEG_' + (idx + 1),
      origin: leg.origin,
      destination: leg.destination,
      departure: leg.departureDateTime,
      arrival: leg.arrivalDateTime,
      airline: leg.carrierCode,
      flightNumber: leg.carrierCode + leg.flightNumber,
      cabin: this.mapCabin(leg.cabinClassCode)
    }));

    const taxDetails: Record<string, number> = {};
    if (Array.isArray(raw.taxes)) {
      raw.taxes.forEach((tax: { code: string; amount: number }) => {
        taxDetails[tax.code] = (taxDetails[tax.code] || 0) + Number(tax.amount);
      });
    }

    return {
      offerId: String(raw.id),
      provider: raw.isNdc ? 'SABRE_NDC' : 'SABRE_GDS',
      validatingCarrier: raw.validatingCarrier || raw.flights[0].carrierCode,
      segments,
      ancillaries: (raw.services || []).map((srv: any) => ({
        serviceId: srv.id,
        serviceType: srv.type || 'BAGGAGE',
        commercialName: srv.name || 'Service Optionnel',
        amount: Number(srv.price?.total || 0),
        currency: srv.price?.currency || 'EUR',
        segmentRefIds: srv.flightRefs || []
      })),
      pricing: {
        baseFare: Number(raw.pricing?.baseFare || 0),
        taxes: Number(raw.pricing?.totalTax || 0),
        total: Number(raw.pricing?.totalAmount || 0),
        currency: raw.pricing?.currency || 'EUR',
        taxBreakdown: taxDetails
      }
    };
  }
}
\end{lstlisting}

\section{Gestion Découplée des Segments Passifs Amadeus et Sabre}

Un billet émis en NDC direct est enregistré chez le transporteur, hors inventaire actif du GDS de l'agence. Pourtant, pour que Gestour, IEnterprise ou l'équivalent génère la facture et les flux de trésorerie, un \textbf{segment passif} informatif doit être posé dans le GDS de référence de l'agence.

Une mauvaise coordination produit des doubles écritures passives --- ou des écritures incohérentes --- sanctionnées par des avis de débit (\textit{Agency Debit Memos} / ADM). J'ai donc livré la migration \texttt{split-passive-segment-options}, qui isole les paramètres d'écriture passive par point de vente. Avant notification, le contrôleur vérifie le canal d'émission : dossier traité sur Sabre $\Rightarrow$ écriture passive Amadeus désactivée. Un seul enregistrement comptable par dossier.

\section{Synchronisation des Dossiers Voyageurs (PNR)}

Un dossier de transport vit plusieurs semaines ou mois, avec des changements externes (horaires, annulation partielle). Dans \texttt{retrieve.controller.js}, la fonction \texttt{keepOnlyMatchingTravelers} réconcilie les passagers rafraîchis depuis le GDS distant avec l'état local, pour éviter de corrompre les enregistrements quand plusieurs agents ouvrent le même dossier.

\section{Algorithme Déterministe de Réconciliation des Passagers}

En début de projet, les rejets NDC (Air France, British Airways) étaient fréquents. Les XML d'erreur montraient souvent un détail de saisie : prénom accentué (« Éléonore »), apostrophe (« D'ALMEIDA »), bébé sans siège sans balise de rattachement adulte. Quand un voyageur était retiré du panier, des bagages restaient parfois accrochés à un identifiant fantôme.

\texttt{matchesPaxRefId} dans \texttt{orderCreation.utils.ts} (listing \ref{lst:matchespaxrefid}) corrige ces cas : nettoyage ASCII 7-bit, lien nourrisson $\rightarrow$ adulte (\texttt{associatedAdultRefId}), purge des services orphelins.

\begin{lstlisting}[language=TypeScript, caption={Algorithme de réconciliation des passagers et gestion des cas limites (\texttt{orderCreation.utils.ts})}, label={lst:matchespaxrefid}]
export interface RawTravelerInput {
  id?: string;
  type: 'ADT' | 'CHD' | 'INF';
  firstName: string;
  lastName: string;
  dateOfBirth?: string;
  assignedAdultIndex?: number; // Requis si type === 'INF'
}

export interface NormalizedPassenger {
  paxRefId: string;
  ptc: 'ADT' | 'CHD' | 'INF';
  givenName: string;
  surname: string;
  birthDate?: string;
  associatedAdultRefId?: string;
}

export function sanitizeIataName(name: string): string {
  return name
    .normalize('NFD')
    .replace(/[\u0300-\u036f]/g, '') // Supprime accents et diacritiques
    .replace(/[^a-zA-Z\s]/g, ' ')   // Remplace tirets et apostrophes par espaces
    .replace(/\s+/g, ' ')           // Reduit les espaces multiples
    .trim()
    .toUpperCase();
}

export function matchesPaxRefId(
  travelers: RawTravelerInput[],
  selectedAncillaries: Array<{ serviceId: string; targetPaxId: string }>
): {
  passengers: NormalizedPassenger[];
  validAncillaries: Array<{ serviceId: string; paxRefId: string }>;
} {
  if (!travelers || travelers.length === 0) {
    throw new Error('[matchesPaxRefId] Aucun voyageur fourni pour la commande');
  }

  const adultRefIds: string[] = [];
  const normalizedPaxList: NormalizedPassenger[] = [];

  // 1. Passe 1 : Traitement et enregistrement des Adultes et Enfants
  travelers.forEach((pax, index) => {
    const generatedRefId = 'PAX' + (index + 1);
    const cleanFirst = sanitizeIataName(pax.firstName);
    const cleanLast = sanitizeIataName(pax.lastName);

    if (pax.type === 'ADT') {
      adultRefIds.push(generatedRefId);
    }

    if (pax.type !== 'INF') {
      normalizedPaxList.push({
        paxRefId: generatedRefId,
        ptc: pax.type,
        givenName: cleanFirst,
        surname: cleanLast,
        birthDate: pax.dateOfBirth
      });
    }
  });

  // 2. Passe 2 : Traitement des Nourrissons (INF) et rattachement adulte
  travelers.forEach((pax, index) => {
    if (pax.type === 'INF') {
      const generatedRefId = 'PAX' + (index + 1);
      const adultTargetRef = adultRefIds[pax.assignedAdultIndex ?? 0] || adultRefIds[0];

      if (!adultTargetRef) {
        throw new Error('[matchesPaxRefId] Nourrisson sans adulte valide : ' + pax.firstName);
      }

      normalizedPaxList.push({
        paxRefId: generatedRefId,
        ptc: 'INF',
        givenName: sanitizeIataName(pax.firstName),
        surname: sanitizeIataName(pax.lastName),
        birthDate: pax.dateOfBirth,
        associatedAdultRefId: adultTargetRef
      });
    }
  });

  // 3. Purge des services ancillaires orphelins
  const validPaxIdSet = new Set(normalizedPaxList.map(p => p.paxRefId));
  const validAncillaries = (selectedAncillaries || [])
    .filter(anc => validPaxIdSet.has(anc.targetPaxId))
    .map(anc => ({ serviceId: anc.serviceId, paxRefId: anc.targetPaxId }));

  return {
    passengers: normalizedPaxList,
    validAncillaries
  };
}
\end{lstlisting}

\chapter{Optimisation du Moteur de Recherche et Filtrage Multi-Compagnies}
\label{chap:moteur_recherche}

\section{Composant de Filtrage et Persistance des Préférences}

En SBT entreprise, les travel managers restreignent souvent les résultats aux alliances contractées (SkyTeam, Star Alliance, Oneworld) ou excluent des low-cost.

\texttt{SelectCompanies.vue} propose deux modes : liste blanche (compagnies conventionnées) et liste noire (transporteurs écartés, reste du marché interrogé).

Les préférences vivent dans Pinia pour la session courante et dans le \texttt{localStorage} du navigateur. Pas d'aller-retour SQL pour un simple réglage d'affichage.

\section{Optimisation des Requêtes de Recherche Serveur}

Le goulot reste la latence des fournisseurs. Dans \texttt{api-aerial}, \texttt{createShoppingPayload} (\texttt{shopping.utils.js}) filtre les compagnies exclues \emph{avant} de construire le XML/JSON. On n'appelle que les connecteurs utiles, au lieu d'interroger tout le monde pour jeter ensuite. Sur les recherches complexes, le gain se compte en centaines de millisecondes.

Deux autres réglages : paramètre \texttt{'W'} injecté dans les requêtes Sabre pour privilégier les directs (demande fréquente en voyage d'affaires) ; dates normalisées en ISO 8601 via \texttt{createDepartureWindow}, pour que Sabre et NDC interprètent la même fenêtre horaire.

\chapter{Architecture Financière et Traitement Asynchrone Multi-Devises}
\label{chap:architecture_financiere}

\section{Résolution Asynchrone de la Devise Point de Vente}

Sur le module facturation / conversion, les SQL synchrones qui résolvaient \texttt{agencyCurrency} saturaient le pool dès que plusieurs agences lançaient des recherches en parallèle. Un paramètre quasi statique bloquait tout le pipeline tarifaire.

J'ai déporté la résolution dans un middleware Express asynchrone avec cache mémoire de dix minutes. La devise est lue une fois en tête de requête, injectée dans \texttt{req.context.posCurrency}, puis réutilisée sans nouvel accès SQL. Contention base en baisse, temps de traitement aussi.

Ce n'est pas la solution « idéale » : une invalidation Redis / webhook serait plus fine. Pour une donnée touchée une fois par an par les admins, un cache mémoire Node.js de dix minutes restait le compromis le plus simple à opérer.

\section{Formatage Dynamique et Norme ISO 4217}

Le multi-devises impose ISO 4217. \texttt{formatPrice} et \texttt{OrderRecap.vue} doivent gérer deux décimales (EUR, USD, GBP), zéro (JPY, KRW) et trois (TND, KWD).

Pour les taxes aéroportuaires, on applique l'arrondi bancaire au pair le plus proche (\textit{banker's rounding}). Contrairement à \texttt{Math.round}, qui pousse toujours les demis vers le haut et biaise les totaux sur de gros volumes, l'arrondi bancaire alterne vers le pair. Objectif : égalité stricte entre total facturé et somme des taxes, sans centime parasite.
